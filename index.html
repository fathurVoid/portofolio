Technical Implementation

CampusTask was developed using modern web development tools and practices. The following technologies were used throughout the development process.

Product Catalog extends this stack with React and TypeScript. Its architecture separates UI, routing, state, data access, and persistence into focused modules; the cards below describe the implementation in more detail.

Git and GitHub

Git is a distributed version control system used to track source code changes. GitHub hosts the repository and supports collaboration through branches and pull requests. Development involved creating branches, committing changes, merging pull requests, and resolving merge conflicts.

npm

npm is a package manager used to install and manage project dependencies. The package.json file defines dependencies, development dependencies, and scripts such as development, type checking, and production builds.

TypeScript

TypeScript extends JavaScript with static typing. CampusTask uses primitive types, arrays, interfaces, type aliases, union types, and generics to improve code reliability and maintainability.

Vite

Vite provides the local development server and production build process. It offers fast development feedback and processes application modules and assets for deployment.

Compiler, Transpiler, and Bundler

The TypeScript compiler (tsc) checks types and reports errors before production builds. TypeScript is also transformed into JavaScript. Vite uses its build pipeline to bundle application modules and assets into optimized production files.

Environment Variables

Environment variables separate application configuration from source code. CampusTask uses variables such as VITE_APP_NAME, VITE_APP_VERSION, VITE_APP_ENV, and VITE_BASE_PATH. The .env.example file documents the required configuration, while the local .env file is excluded from Git.

Product Catalog: React and TypeScript Architecture

Product Catalog is built with React 19 and TypeScript. Typed product models, props, and form state are shared across components, pages, hooks, services, context, and utilities so API and locally created products use one normalized shape. Styling uses custom CSS tokens rather than a component library.

Product Catalog: Routing and State Management

React Router DOM defines nested routes under a shared RootLayout with <Outlet />. Routes include /products, /products/new, dynamic /products/:productId, /saved, and a catch-all NotFoundPage. URL state uses useSearchParams for q, category, sortBy, order, page, and limit. Local state handles the debounced search box and controlled form, while SavedProductsContext shares favorites through the Context API.

Product Catalog: Data Fetching and Custom Hooks

A single Axios client requests DummyJSON products, search results, categories, and details. Custom hooks useProducts, useProductDetail, useCategories, useDebounce, and useLocalProducts manage server state, cancellation with AbortController, loading, error, and empty states, plus local persistence. Service functions normalize API responses and handle failed requests.

Product Catalog: Persistence and Separation of Concerns

SavedProductsContext persists favorites to storeSukses:savedProducts:v1, while locally created products use storeSukses:localProducts:v1. Reusable components such as ProductCard, ProductGrid, SearchBar, CategoryFilter, Pagination, StatCards, and ConfirmDialog are composed by pages; services, types, and utilities keep data access and validation separate from presentation.
